How controls apply

Saved values update adminConfig/bot/automod, adminConfig/bot/leveling, adminConfig/bot/links and adminConfig/bot/discord. Panel content is stored under panels/{panelType}. The running Bot listens to these paths and attempts to update the corresponding Discord panel. This does not grant the Bot new Discord permissions: configure Manage Messages, Moderate Members, Manage Channels, and required role permissions in Discord separately.

Implementation notes
• Bot controls include feature switches, live presence, welcome/verification/automod messages, automod thresholds, XP rules, checkout session policy, panel color/footer/placeholder/options and Discord channel/role IDs. The running Bot listens to Firebase changes.
• Reader status uses the existing reader_devices/{uid}.lastSeenAt path. The Bot heartbeat is written to runtime/bot every 30 seconds. Weekly message/voice counters and the weekly report timer use runtime/botStats.
• bKash/Nagad official Merchant API/webhook is not connected in this version because merchant credentials and provider-issued integration details are unavailable. Reader event stays evidence_matched until an Admin checks official history and approves or rejects it.
• Managed Discord panels are created/edited when the Bot is online; moving a panel removes the Bot-owned previous managed message when permissions allow. Hosting process start/restart is not exposed. A database toggle cannot restart a stopped process; secure hosting-provider credentials and a separate authenticated server endpoint would be required. Channel/role ID changes do not change Discord server permissions.
